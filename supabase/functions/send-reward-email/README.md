# Reward email worker

Internal transactional worker for the email sent after a customer earns a
loyalty reward. The browser never invokes this function and never receives a
Resend credential.

## Required Edge Function secrets

- `RESEND_API_KEY`: API key for the verified Spirit Resend account.
- `RESEND_FROM_EMAIL`: verified sender, including the display name if desired.
- `SPIRIT_APP_URL`: optional; defaults to `https://www.spiritcoffee.es/`.

The Supabase runtime provides `SUPABASE_URL` and its server secret. The request
secret is generated by the migration in Supabase Vault and is read by the cron
job at execution time.

The current remote Edge Function secret inventory does not contain
`RESEND_API_KEY` or `RESEND_FROM_EMAIL`; these must be added before activation.
Do not place their values in this repository.

## Activation order

1. Apply `20260729234225_add_reward_email_outbox.sql`.
2. Add the required Edge Function secrets.
3. Deploy `send-reward-email` with JWT verification disabled. The function
   performs its own mandatory Vault-secret verification.
4. Run `supabase/cron/schedule_reward_emails.sql` once in the Spirit project.
5. Confirm that `spirit-reward-email-worker` is active in `cron.job`.

Do not schedule the worker before the migration, secrets, and function exist.

## Controlled manual test

Use a dedicated test account whose inbox is controlled by the tester. Do not
edit an existing customer's card.

1. Create and confirm the test account through the normal customer flow.
2. Confirm that the normal initialization created its Spirit customer card.
3. Use the normal cafeteria stamping flow until the tenth stamp is confirmed.
4. Verify one row in `public.reward_notifications` with `reward_sequence = 1`.
5. Wait for the next one-minute worker run.
6. Verify that the row becomes `sent`, has `attempts = 1`, `sent_at` is set,
   and `provider_message_id` is present.
7. Confirm that the test inbox received one message and that the CTA opens
   `https://www.spiritcoffee.es/`.
8. Re-run the worker and verify that the sent row is not claimed again.
9. Delete the dedicated test account after the check; its card and outbox rows
   cascade according to the existing account-deletion rules.

Automated tests use a mocked Resend transport and never send real email.

Automatic retries stop before Resend's 24-hour idempotency window expires.
An older ambiguous failure remains visible as `failed` for manual review instead
of risking a duplicate delivery.
